## เริ่มใช้งาน

### สำคัญ: ต้อง deploy ใหม่หลังอัปเดตเป็นรุ่น 2

รุ่นนี้นำฟังก์ชัน `refundIfNotDelivered()` และ Event `PaymentRefunded` เดิมออก ไม่อนุญาตให้ผู้ว่าจ้างคืนเงินโดยตรงเมื่อหมดเวลาอีกต่อไป หากยังไม่ส่งงานและเลยกำหนด ให้ **เปิดข้อพิพาท → Admin พิจารณา → คืนเงินหรือจ่ายค่าจ้าง** เงินยังอยู่ใน Escrow ตลอดช่วงรอคำตัดสิน

- Contract ที่เคย deploy ไว้ **ไม่เปลี่ยนตามการแก้ไฟล์ Solidity** ต้อง compile และ deploy โค้ดปัจจุบันใหม่ แล้วเปลี่ยน `CONTRACT_ADDRESS` และ `DEPLOY_BLOCK` ใน `config.js`
- เก็บ address ที่คุณตั้งไว้เดิมใน `config.js` เพื่ออ้างอิง แต่ไม่ได้ถือว่าเป็นรุ่นใหม่ หน้าเว็บตรวจ `CONTRACT_VERSION() == 2` ก่อนเปิดใช้งาน หากไม่มี getter นี้หรือเป็นคนละรุ่น จะไม่เปิดการทำรายการ
- การตรวจรุ่นช่วยป้องกันการใช้ address เก่าโดยไม่ตั้งใจ ไม่ใช่ security audit หรือการยืนยัน bytecode ทั้งหมด ต้องตรวจ address และโค้ดที่ deploy เองด้วย
- งาน ยอดเงิน และประวัติของ contract เก่า **ไม่ย้ายมา contract ใหม่อัตโนมัติ** หากยังมีเงินค้าง ต้องจัดการด้วยกติกาของ contract เก่าแยกต่างหาก การแก้เว็บไม่ปิดฟังก์ชันบน contract เก่าที่ deploy แล้ว

### 1. Deploy smart contract

1. เปิด [Remix IDE](https://remix.ethereum.org/) แล้วนำ `smart-contact/FreelanceEscrow.sol` ไป compile ด้วย Solidity **0.8.26** หรือรุ่นที่รองรับ `^0.8.26`
2. เปิด MetaMask เลือก **Sepolia** และเตรียม Sepolia ETH สำหรับค่า gas
3. ใน Remix เลือก **Deploy & Run Transactions → Injected Provider - MetaMask** ตรวจว่าเป็น Sepolia แล้ว deploy โดยไม่ต้องใส่ constructor arguments
4. บัญชีที่ deploy จะเป็น **Admin / ผู้ตัดสินข้อพิพาท** ตลอดอายุ contract นี้ ไม่มีฟังก์ชันเปลี่ยน Admin
5. ตรวจ getter `CONTRACT_VERSION` ต้องคืนค่า **2** แล้วคัดลอก **contract address** และหมายเลข **block ที่ deploy** จาก receipt หรือ Sepolia Etherscan

### 2. ตั้งค่า `config.js`

```js
window.APP_CONFIG = {
  CONTRACT_ADDRESS: '0xYOUR_DEPLOYED_CONTRACT_ADDRESS',
  CHAIN_ID: 11155111,
  RPC_URL: 'https://ethereum-sepolia-rpc.publicnode.com',
  EXPLORER_URL: 'https://sepolia.etherscan.io',
  DEPLOY_BLOCK: 0,       // แนะนำให้เปลี่ยนเป็น block ที่ deploy จริง
  MAX_LOG_BLOCKS: 10000,
  LOG_CHUNK_SIZE: 1000
};
```

ต้องใช้ address ของ **FreelanceEscrow รุ่น 2 บน Sepolia** ไม่ใช่ address ของ Wallet, contract รุ่นเก่า หรือ contract จาก week อื่น หาก address ว่างหรือรุ่นไม่ตรง หน้าเว็บจะแสดงคำแนะนำ ไม่ใช้ข้อมูลสมมติแทนข้อมูลจริง

| ค่า | หน้าที่ |
| --- | --- |
| `CONTRACT_ADDRESS` | Contract ที่ deploy และต้องการใช้งาน |
| `CHAIN_ID` | รองรับ Sepolia เท่านั้น (`11155111`) |
| `RPC_URL` | HTTP(S) RPC ของ Sepolia สำหรับอ่านข้อมูลสาธารณะ ใช้ endpoint อื่นที่มีสิทธิ์ใช้ได้หาก public RPC จำกัดคำขอ |
| `EXPLORER_URL` | URL ของ Sepolia Etherscan สำหรับลิงก์ address และ transaction |
| `DEPLOY_BLOCK` | บล็อกเริ่มต้นในการค้นหา Events ไม่กระทบ getter ของประวัติเงิน |
| `MAX_LOG_BLOCKS` | จำนวนบล็อกย้อนหลังสูงสุดที่ค้นหา Events ต่อครั้ง เพิ่มได้หากต้องการกิจกรรมเก่ากว่านี้ แต่ใช้ RPC มากขึ้น |
| `LOG_CHUNK_SIZE` | จำนวนบล็อกต่อคำขอ `eth_getLogs` ลดค่านี้เมื่อ RPC จำกัดช่วง |

### 3. เปิดเว็บไซต์

เปิด Terminal จาก root ของ repository:

```bash
cd week8
python -m http.server 5500
```

จากนั้นเปิด **http://localhost:5500** หรือใช้ VS Code Live Server โดยเปิด `week8/index.html` ไม่แนะนำ `file://`

- ต้องมีอินเทอร์เน็ตเพื่อโหลด Tailwind CDN, ethers.js และ RPC ส่วนฟอนต์โหลดจากไฟล์ local
- อ่านรายการงาน รายละเอียด และประวัติได้โดยไม่เชื่อม Wallet
- กด **เชื่อมต่อ Wallet** เมื่อต้องการทำธุรกรรม ใช้ MetaMask / EIP-1193 Wallet (`window.ethereum`)
- หากอยู่คนละเครือข่าย กด **เปลี่ยนเป็น Sepolia** ทุกธุรกรรมให้ผู้ใช้ยืนยันผ่าน Wallet ไม่มี backend เก็บกุญแจ
- หากสลับบัญชีหรือเครือข่าย ระบบจะปิดฟอร์มเดิมและโหลดสิทธิ์ใหม่

## ฟังก์ชันตามโจทย์

| ข้อ | การทำงานในหน้าเว็บ | ฟังก์ชัน / ข้อมูลจาก contract |
| --- | --- | --- |
| 1. สร้างข้อตกลง | ผู้ว่าจ้างกรอกชื่อ รายละเอียด Wallet ฟรีแลนซ์ ค่าจ้าง ETH และกำหนดส่ง | `createJob` |
| 2. ฝากเงิน Escrow | เปิดรายละเอียด → ฝากค่าจ้าง ระบบใช้ `job.amount` เป็น `msg.value` ให้ตรงพอดี | `depositPayment` |
| 3. ส่งมอบงาน | เฉพาะฟรีแลนซ์ของงาน กรอก URL หรือ Hash ของผลงาน | `submitWork` |
| 4. ตรวจรับและจ่าย | เฉพาะผู้ว่าจ้างตรวจหลักฐาน แล้วอนุมัติโอน ETH ทั้งจำนวนให้ฟรีแลนซ์ | `approveAndRelease` |
| 5. จัดการข้อพิพาท | คู่สัญญาเปิดข้อพิพาทพร้อมเหตุผล Admin เลือกจ่ายให้ฟรีแลนซ์หรือคืนผู้ว่าจ้าง | `raiseDispute`, `resolveDispute` |
| 6. ติดตามธุรกรรม | สถานะงาน ประวัติเงิน ผู้รับ จำนวน เวลา Events และลิงก์ Transaction Hash บน Etherscan | `getJob`, `getPaymentHistory`, Events และ transaction receipt |
| ฟังก์ชันเสริม | ยกเลิกก่อนฝากเงินเท่านั้น ไม่มีเงินออกจาก Escrow | `cancelJob` |
| Dashboard | จำนวนงานทั้งหมด ยอด ETH ใน contract งานที่ว่าจ้าง/รับ และบทบาท Wallet | `jobCount`, `escrowBalance`, `getJobsByClient`, `getJobsByFreelancer`, `admin` |

**งานที่ฉันว่าจ้าง / งานที่ฉันรับ** ใช้ address ที่เชื่อม Wallet ส่วน **ข้อพิพาท** เป็นตัวกรองงานสาธารณะที่โหลดแล้ว ไม่ได้ทำให้ผู้ใช้ทั่วไปได้รับสิทธิ์ Admin ผู้ใช้หนึ่งบัญชีเป็นผู้ว่าจ้างในงานหนึ่งและฟรีแลนซ์ในงานอื่นได้ สิทธิ์จึงตรวจเป็นรายงาน

## สถานะและสิทธิ์

```text
Created ──ฝากเงิน──> Funded ──ส่งงาน──> Submitted ──ผู้ว่าจ้างอนุมัติ──> Approved
Created ──ยกเลิกก่อนฝากเงิน──> Cancelled

Funded หรือ Submitted ──คู่สัญญาเปิดข้อพิพาท──> Disputed
Disputed ──Admin ตัดสินจ่าย──> Resolved (จ่ายฟรีแลนซ์)
Disputed ──Admin ตัดสินคืน───> Refunded (คืนผู้ว่าจ้าง)

พ้นกำหนดและยังไม่ส่ง: คงสถานะ Funded และล็อกเงินไว้ → เปิดข้อพิพาท → รอ Admin
```

| ค่า / สถานะ | ทำอะไรได้ |
| --- | --- |
| `0 Created` รอฝากเงิน | ผู้ว่าจ้างฝากก่อน deadline หรือยกเลิก (ยกเลิกได้แม้พ้นกำหนด หากยังไม่ฝาก) |
| `1 Funded` กำลังดำเนินงาน | ฟรีแลนซ์ส่งได้ถึง deadline; คู่สัญญาเปิดข้อพิพาทได้ทั้งก่อนและหลังกำหนด ไม่มีการคืนเงินโดยตรง |
| `2 Submitted` รอตรวจรับ | ผู้ว่าจ้างอนุมัติจ่าย หรือคู่สัญญาเปิดข้อพิพาทได้ แม้พ้นกำหนดส่งแล้ว |
| `3 Approved` อนุมัติแล้ว | จบงาน จ่ายฟรีแลนซ์แล้ว |
| `4 Disputed` มีข้อพิพาท | เฉพาะ Admin ตัดสินทั้งหมดให้ฝ่ายใดฝ่ายหนึ่ง |
| `5 Resolved` ตัดสินให้จ่ายแล้ว | จบงาน จ่ายฟรีแลนซ์โดยคำตัดสินแล้ว |
| `6 Refunded` คืนเงินแล้ว | จบงาน คืนผู้ว่าจ้างตามคำตัดสิน Admin แล้วเท่านั้น |
| `7 Cancelled` ยกเลิกแล้ว | จบงาน ยกเลิกก่อนฝากเงิน |

ปุ่มแสดงตาม Wallet สถานะ และเวลา แต่ **contract เป็นผู้บังคับกฎขั้นสุดท้าย** ไม่ใช่การซ่อนปุ่มเพียงอย่างเดียว UI ใช้เวลาท้องถิ่นของอุปกรณ์ช่วยเปิด/ปิดปุ่ม ส่วน contract ใช้ `block.timestamp` จึงอาจต่างกันเล็กน้อยใกล้ deadline

### กฎธุรกิจ: ห้ามจ่ายซ้ำและห้ามถอนก่อนเข้าเงื่อนไข

- มีเพียง `approveAndRelease` (ผู้ว่าจ้าง + `Submitted`) และ `resolveDispute` (Admin + `Disputed`) ที่โอน ETH ออกจาก Escrow
- `raiseDispute` เปลี่ยนสถานะและบันทึกเหตุผลเท่านั้น **ไม่โอนเงิน** แม้พ้น deadline แล้ว
- ทั้งสองฟังก์ชันจ่ายเงินเปลี่ยนสถานะเป็นสถานะจบก่อนเรียกผู้รับ และมี `nonReentrant` ป้องกันการเรียกซ้อน การอนุมัติ/ตัดสินซ้ำจะถูกปฏิเสธ
- ไม่มีฟังก์ชันถอนทั่วไปหรือคืนเงินเพราะหมดเวลา การเรียก selector ของ `refundIfNotDelivered` แบบเก่าตรงไปยัง contract รุ่น 2 จะถูก fallback ปฏิเสธ ไม่ใช่เพียงซ่อนปุ่มบนเว็บ

## ตัวอย่างทดสอบครบวงจร

เตรียม **A = ผู้ว่าจ้าง**, **B = ฟรีแลนซ์**, **C = Admin ที่ deploy** (C อาจเป็น A ได้ตาม contract) และ Sepolia ETH สำหรับ gas ทุกบัญชี ทั้งหมดใช้ address ของ contract เดียวกัน

### เส้นทางปกติ

1. A เชื่อม Wallet → **สร้างข้อตกลงใหม่** → ใส่ชื่อ รายละเอียด address ของ B ค่าจ้าง `0.001` ETH และเวลาส่งในอนาคต → ยืนยันใน Wallet
2. รอธุรกรรมสำเร็จ จด **Job ID** และเปิด Transaction บน Etherscan ตรวจว่าสถานะเป็น **รอฝากเงิน** ยังไม่เกิดการโอนค่าจ้าง (เสียเฉพาะ gas)
3. A เปิดรายละเอียดงาน → **ฝากค่าจ้างเข้า Escrow** ตรวจมูลค่าใน Wallet ว่า `0.001` ETH + gas → รอเป็น **กำลังดำเนินงาน** ตรวจประวัติ `DEPOSIT`
4. สลับเป็น B → **งานที่ฉันรับ** → เปิดงาน → **ส่งมอบผลงาน** → ใส่ URL/Hash → รอเป็น **รอตรวจรับ**
5. A ตรวจหลักฐาน → **อนุมัติและจ่ายค่าจ้าง** → ยืนยัน → รอเป็น **อนุมัติแล้ว** ตรวจประวัติ `RELEASE`, ผู้รับเป็น B และยอด Escrow ลดลง
6. เปิด **โหลด Events** ในรายละเอียดเพื่อตรวจลำดับกิจกรรมและ Transaction Hash สถานะที่จบแล้วต้องไม่มีปุ่มจ่ายซ้ำ

### เส้นทางข้อพิพาทและคืนเงิน

7. สร้างงานใหม่และฝากเงิน → A หรือ B **เปิดข้อพิพาท** ใส่เหตุผล → รอเป็น **มีข้อพิพาท** ปุ่มส่งงาน/อนุมัติหายไป
8. สลับเป็น C → เมนู **ข้อพิพาท** → เปิดงาน → **ตัดสินข้อพิพาท** → เลือก **จ่ายค่าจ้างทั้งหมดให้ฟรีแลนซ์** → รอ **ตัดสินให้จ่ายแล้ว** ประวัติต้องมี `DISPUTE_PAYOUT`
9. ทดสอบข้อ 7–8 กับงานใหม่ แต่เลือก **คืนค่าจ้างทั้งหมดให้ผู้ว่าจ้าง** → รอ **คืนเงินแล้ว** ประวัติต้องมี `REFUND`
10. สร้างงานใหม่ กำหนดส่งอีกไม่กี่นาที ฝากก่อนกำหนด และไม่ส่งงาน → รอเลย deadline → A เปิดรายละเอียด ต้องไม่มีปุ่มคืนเงินโดยตรงและเงินยังล็อกอยู่ → **เปิดข้อพิพาท** ระบุว่ายังไม่ส่งงาน → เงินยังไม่ออก → C **ตัดสินข้อพิพาท** เลือกคืนผู้ว่าจ้าง → ตรวจ `REFUND` และ Event `DisputeResolved` ที่ `paidToFreelancer = false`
11. สร้างอีกงานที่ยังไม่ฝาก → A **ยกเลิกข้อตกลง** → สถานะ **ยกเลิกแล้ว** ประวัติเงินว่าง ไม่มีการคืนเงินเพราะยังไม่เคยฝาก

### สิทธิ์และข้อมูลไม่ถูกต้อง

- บัญชีที่ไม่ใช่คู่สัญญาต้องอ่านได้ แต่ฝาก/ส่ง/อนุมัติ/เปิดข้อพิพาทไม่ได้ และบัญชีที่ไม่ใช่ Admin ตัดสินไม่ได้
- ลองผู้ว่าจ้างและฟรีแลนซ์ address เดียวกัน, Zero Address, ค่าจ้าง `0`, เลขติดลบ, ทศนิยมเกิน 18 หลัก, deadline ในอดีต และข้อความว่าง ต้องถูกปฏิเสธ
- เปลี่ยน Wallet เป็นเครือข่ายอื่น ปุ่มเขียนต้องปิดและมีปุ่มเปลี่ยนเป็น Sepolia
- ลองปฏิเสธคำขอใน Wallet ต้องแสดงข้อความและเปิดให้ลองใหม่ ไม่สร้างข้อมูลสำเร็จปลอม
- เปิดด้วยจอมือถือ ตรวจเมนูที่เลื่อนได้ การ์ด และฟอร์มโดยไม่เกิด horizontal overflow

## ประวัติและการโหลดข้อมูล

- โครงการโหลดล่าสุดก่อน **ครั้งละ 8 งาน** มีปุ่มโหลดเพิ่ม ค้นหาชื่อ/Job ID และกรองสถานะ **เฉพาะรายการที่โหลดแล้ว** หากไม่พบงานเก่า ให้โหลดเพิ่มหรือกรอก Job ID โดยตรงด้านล่าง
- ภาพรวมจำนวนงาน / ยอด Escrow มาจาก getter ไม่ใช่ผลรวมเฉพาะการ์ดที่โหลดแล้ว ส่วนยอด Wallet แสดงแยกเพื่อไม่ให้สับสนกับเงินที่ล็อกอยู่
- **ประวัติเงิน** มาจาก `getPaymentHistory(jobId)` ครบทุก record ของงาน ไม่ขึ้นกับช่วงค้นหา Events แต่ getter นี้ **ไม่มี Transaction Hash** จึงต้องโหลด Events เพิ่มหากต้องการ hash หรือเหตุผลข้อพิพาท
- **กิจกรรม** อ่าน Event จริงตาม Job ID แบ่งช่วงบล็อกตาม config แสดงช่วงที่ค้นหาชัดเจน หากไม่มี Event ในช่วงนั้น ไม่ได้แปลว่าไม่มีประวัติ การอ่าน Events ล้มเหลวจะไม่ลบประวัติเงิน
- ธุรกรรมที่ส่งจากหน้าเว็บแสดง hash ทันที รอ receipt **1 confirmation** แล้วอ่านข้อมูลใหม่ หากรีเฟรชหลังยืนยันล้มเหลว ระบบจะแจ้งว่า **สำเร็จแล้ว ไม่ต้องส่งซ้ำ**
- หาก RPC/Wallet ขาดการเชื่อมต่อหลังส่ง หรือมีการแทนที่/ยกเลิกธุรกรรม ให้ตรวจสถานะจริงและ hash บน Etherscan ก่อนลองใหม่ หน้ารายการธุรกรรมล่าสุดอยู่ในหน่วยความจำและไม่คงอยู่หลัง reload แต่ข้อมูลบน contract ยังคงอยู่
- หาก public RPC ตามบล็อกล่าสุดไม่ทัน ข้อมูลอาจยังเป็นสถานะเก่าชั่วคราว ให้รอสักครู่แล้วกดรีเฟรช ไม่ใช่เหตุผลให้ส่งรายการเดิมซ้ำ

## ขอบเขตและข้อควรระวังของ contract

- ค่าจ้างเป็น ETH ไม่ใช่ ERC-20 ไม่มีค่าบริการแพลตฟอร์ม ค่าจ้างส่งเป็น wei ผ่าน `ethers.parseEther` โดยไม่ใช้ floating point และไม่รวมค่า gas
- สร้างงานไม่ฝากเงินอัตโนมัติ การฝากต้องตรงจำนวนเพียงครั้งเดียว **ก่อน** deadline (`<`) ฟรีแลนซ์ส่งงานได้ **ถึง** deadline (`<=`) ส่วนการคืนเงินต้องผ่านคำตัดสิน Admin ในสถานะ `Disputed` ไม่ได้ปลดล็อกด้วยเวลา
- ชื่อ รายละเอียด จำนวนเงิน ฟรีแลนซ์ และ deadline แก้ไม่ได้หลังสร้าง ไม่มี milestone แบ่งจ่าย ต่อเวลา ส่งแก้งาน หรือเปลี่ยนฟรีแลนซ์
- การฝาก/ส่ง/คืนเงิน/อนุมัติ **ไม่ได้ทำอัตโนมัติตามเวลา** ต้องมีผู้มีสิทธิ์ส่งธุรกรรม การอนุมัติเป็นคำสั่งที่ทำให้ contract โอน ETH ในธุรกรรมเดียวกัน
- แม้ยังไม่ส่งงาน ผู้ว่าจ้างก็คืนเงินโดยตรงเพราะหมดเวลาไม่ได้ ต้องเปิดข้อพิพาทและรอ Admin หากส่งงานแล้วให้ตรวจรับหรือเปิดข้อพิพาท ไม่มี auto-approval หรือ timeout สำหรับการตรวจรับ / คำตัดสิน Admin
- ข้อพิพาทเปิดได้ใน `Funded` หรือ `Submitted` รวมถึงหลัง deadline แล้ว Admin จ่ายเต็มจำนวนให้ฟรีแลนซ์หรือคืนเต็มจำนวนให้ผู้ว่าจ้างเท่านั้น
- เหตุผลข้อพิพาทอยู่ใน Event ไม่ได้อยู่ใน struct `Job` ผลงานเป็นข้อความ URL/Hash contract ไม่อัปโหลด เก็บไฟล์ หรือรับประกันว่า URL เข้าถึงได้ และไม่ตรวจคุณภาพ/ความจริงของผลงาน
- UI ขอเหตุผลข้อพิพาทที่ไม่ว่าง และจำกัดชื่อ 200, รายละเอียด 5,000, หลักฐาน/เหตุผล 3,000 ตัวอักษรเพื่อ UX ข้อจำกัดเหล่านี้ไม่ใช่ข้อบังคับทั้งหมดใน Solidity (เช่น contract อนุญาตเหตุผลว่าง)
- ข้อมูลบนเชนและ Events เป็นสาธารณะ ห้ามใส่ชื่อจริง ข้อมูลส่วนตัว ลิงก์ที่มี access token หรือความลับ ลิงก์ผลงานเปิดเฉพาะ HTTP(S) ส่วน Hash/IPFS URI แสดงเป็นข้อความเพื่อคัดลอก ข้อความบนเชนถูก escape ก่อนแสดงใน HTML
- Contract ปฏิเสธการส่ง ETH ตรงผ่าน `receive` / `fallback` ต้องฝากด้วย `depositPayment` เท่านั้น ผู้รับที่เป็น contract และรับ ETH ไม่ได้ทำให้ธุรกรรมจ่ายเงิน revert
- อ่านข้อมูลสาธารณะได้โดยไม่เชื่อม Wallet ไม่ใช่ระบบล็อกอินหรือซ่อนงานลับ และต้องตรวจ contract address / ความน่าเชื่อถือของ Admin เอง
- Tailwind Play CDN เหมาะกับ lab ไม่ใช่ production build สำหรับข้อมูลมากควรเพิ่ม indexer และ pagination ฝั่งข้อมูล; ปัจจุบัน getter รายการ ID/ประวัติเงินคืน array ทั้งหมด และการอ่านหลายคำขอไม่ใช่ snapshot บล็อกเดียวกัน

## การตรวจสอบระหว่างพัฒนา

- Compile contract รุ่น 2 ด้วย Solidity **0.8.26** และเทียบ ABI ของ frontend กับ ABI ที่ compile ได้ครบทุกฟังก์ชัน/Events
- ทดสอบผ่านหน้าเว็บด้วย **Playwright + Chrome** กับ contract ที่ deploy บน **Ganache ภายในเครื่อง** โดยใช้ EIP-1193 test bridge แทนการเซ็นผ่าน MetaMask จริง
- ตรวจเส้นทางสร้าง/ฝาก/ส่ง/อนุมัติ ข้อพิพาททั้งสองผลลัพธ์ ยกเลิก กรณีพ้นกำหนดต้องรอ Admin สิทธิ์แต่ละบัญชี การปฏิเสธธุรกรรม การสลับเครือข่าย การค้นหา/โหลดเพิ่ม และการโหลดฟอนต์ local
- ตรวจเวลา `<`, `<=` ตรง deadline, ความแม่นยำ wei, การ escape ข้อความ และหน้าจอ desktop/mobile ไม่ล้น

Regression tests สำหรับกฎการจ่ายเงินอยู่ใน `tests/requirements.test.cjs` ใช้ Node.js 20+ และติดตั้ง dependencies **เฉพาะสำหรับทดสอบ** (การเปิดเว็บตามปกติยังไม่ต้องใช้ npm):

```bash
cd week8/tests
npm install
npm test
```

ทดสอบการเรียก selector คืนเงินเดิมก่อน/หลัง deadline, การล็อกเงินระหว่างข้อพิพาท, สิทธิ์ Admin, การจ่าย/คืนซ้ำ, การโจมตีเรียกซ้อน, การโอนล้มเหลวและ ABI/สิทธิ์ใน frontend โดยไม่ใช้ Sepolia หรือ private key จริง

การทดสอบนี้ **ไม่ใช่การ deploy หรือทดสอบบน Sepolia จริง** ต้องใส่ contract address รุ่นใหม่ของคุณและทดสอบกับ Wallet ตามขั้นตอนด้านบนอีกครั้ง ชุดทดสอบไม่ได้เป็น dependency ของเว็บ

## แก้ปัญหาเบื้องต้น

| อาการ | วิธีตรวจ |
| --- | --- |
| มีแถบให้ตั้งค่า address | Deploy แล้วใส่ `CONTRACT_ADDRESS` ใน `config.js` จากนั้น reload |
| แจ้งว่า contract เป็นรุ่นเก่า / ไม่รองรับ CONTRACT_VERSION | Deploy โค้ดรุ่น 2 ใหม่ ตรวจ getter ได้ `2` แล้วเปลี่ยน address และ deploy block; แก้ไฟล์อย่างเดียวไม่เปลี่ยน contract เดิมบนเชน |
| ไม่พบ bytecode / อ่านข้อมูลไม่ได้ | ตรวจว่าเป็น FreelanceEscrow บน Sepolia จริง ตรวจ RPC / อินเทอร์เน็ต / CDN และ reload |
| ปุ่มสร้างหรือทำรายการปิด | เชื่อม Wallet ตรวจ network สิทธิ์ สถานะงาน deadline และรอธุรกรรมปัจจุบันให้เสร็จ |
| ค่า gas หรือเงินไม่พอ | เตรียม Sepolia ETH ทั้งค่าจ้างและ gas; ฟรีแลนซ์/Admin ต้องมี gas เช่นกัน |
| โหลด Events ไม่ได้ | ลด `LOG_CHUNK_SIZE`, ลด `MAX_LOG_BLOCKS`, ใส่ `DEPLOY_BLOCK` จริง หรือเปลี่ยน RPC |
| ไม่พบกิจกรรมเก่า | เพิ่ม `MAX_LOG_BLOCKS` ให้ครอบคลุมตั้งแต่ deploy; ประวัติเงินใช้ getter คนละส่วน |
| สถานะ/เวลาไม่ตรง | ตรวจเวลาของอุปกรณ์ รอ RPC อัปเดต และรีเฟรช Contract ใช้เวลาจากบล็อก |
