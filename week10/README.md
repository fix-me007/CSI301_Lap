## เริ่มใช้งาน

1. เปิด [Remix IDE](https://remix.ethereum.org/) แล้วนำ `smart-contact/DigitalCertificate.sol` ไป compile ด้วย Solidity **0.8.26** หรือรุ่น 0.8.x ที่รองรับ `^0.8.26`
2. ใน **Deploy & Run Transactions** เลือก **Injected Provider - MetaMask** และเครือข่าย **Sepolia** จากนั้น deploy โดยไม่ต้องใส่ constructor arguments บัญชี deploy จะเป็นทั้ง **Admin และ Issuer**
3. ตรวจสอบหรือใส่ address ของ **contract ที่ deploy** ใน `week10/config.js` ให้ตรงกับ contract ของคุณ หากยังไม่ได้ deploy ให้เว้น address ว่างไว้ หน้าเว็บจะแจ้งให้ตั้งค่าและไม่แสดงข้อมูลจำลองแทนผลจริง:

   ```js
   window.APP_CONFIG = {
     CONTRACT_ADDRESS: '0xYOUR_DEPLOYED_CONTRACT_ADDRESS',
     CHAIN_ID: 11155111,
     RPC_URL: 'https://ethereum-sepolia-rpc.publicnode.com',
     EXPLORER_URL: 'https://sepolia.etherscan.io'
   };
   ```

4. เปิด local HTTP server จากโฟลเดอร์นี้ เช่น:

   ```bash
   cd week10
   python -m http.server 5500
   ```

5. เปิด **http://localhost:5500** ในเบราว์เซอร์ หรือใช้ VS Code Live Server ไม่ควรเปิดด้วย `file://`
6. ต้องมีอินเทอร์เน็ตสำหรับ Tailwind CDN, ethers.js, QRCode.js และ RPC ส่วนฟอนต์โหลดจากไฟล์ local บัญชีที่ทำธุรกรรมต้องมี **Sepolia ETH สำหรับค่า gas**

**ไม่ใส่ private key หรือ seed phrase ในไฟล์ใด ๆ ของ frontend** การเซ็นธุรกรรมทำผ่าน Wallet เท่านั้น ผู้เยี่ยมชมอ่านข้อมูลผ่าน Public RPC ได้โดยไม่เชื่อม Wallet

## วิธีสร้างและตรวจ Hash

### โหมดหลัก: PDF V1 — ป้องกันการแก้ไขเอกสารจริง

เวอร์ชันแรก Hash เฉพาะข้อมูลรหัส/ชื่อ/salt ซึ่งยังพิสูจน์ความครบถ้วนของ PDF ไม่ได้ จึงเพิ่มโหมด **PDF V1** เป็นค่าเริ่มต้นเพื่อให้ตรงกับ Business Scenario ที่มีการแก้ชื่อหรือรายละเอียดในใบรับรอง PDF

1. เตรียม **PDF ฉบับสมบูรณ์** ที่มีชื่อผู้รับ หลักสูตร และรายละเอียดถูกต้อง หากใส่ QR ลงใน PDF ให้ใส่ก่อนคำนวณ Hash โดยใช้ URL `https://your-site/?certId=รหัสใบรับรอง#verify` ไม่ต้องรอออกใบรับรองเพื่อสร้าง URL
2. ในหน้าออกใบรับรอง กด **สร้าง Hash แบบ off-chain** เลือก **PDF V1** แล้วเลือก PDF ขนาดไม่เกิน **20 MiB** ระบบตรวจส่วนหัว `%PDF-` และอ่านทุกไบต์ในเบราว์เซอร์ ไม่ใช่เฉพาะข้อความที่เห็น และไม่อัปโหลดไฟล์
3. ตรวจ certId/courseId ให้ตรงกับข้อมูลในฟอร์ม ระบบสุ่ม salt 32 bytes ด้วย `crypto.getRandomValues` ตอนออกใบรับรอง
4. **เก็บ PDF ต้นฉบับ วิธี Hash รหัสทั้งสอง และ salt อย่างปลอดภัยนอกเชน** แล้วกดใช้ Hash และออกใบรับรอง ต้องมีช่องทางส่ง PDF และ salt ให้ผู้ตรวจที่มีสิทธิ์ ไม่ใช้ QR สาธารณะเป็นที่เก็บ salt
5. ผู้ตรวจเปิดรหัสหรือ QR → **คำนวณ Hash จาก PDF / ข้อมูล** → เลือก **PDF V1** → เลือกไฟล์ที่ต้องการตรวจ กรอกรหัสหลักสูตรและ **salt เดิม** แล้วกดใช้ Hash และตรวจสอบ ไม่ต้องเชื่อม Wallet

สูตร PDF V1:

```js
const pdfDigest = ethers.keccak256(new Uint8Array(await file.arrayBuffer()));
ethers.keccak256(
  ethers.AbiCoder.defaultAbiCoder().encode(
    ['string', 'string', 'string', 'bytes32', 'string'],
    ['SKILLTRUST_PDF_V1', certId, courseId, pdfDigest, salt]
  )
)
```

- เปลี่ยนไบต์ใดใน PDF รวมถึงชื่อ รายละเอียด รูป QR หรือ metadata จะได้ Hash ต่างกัน การ Export/Save ใหม่อาจเปลี่ยน Hash แม้หน้าตาเหมือนเดิม ต้องตรวจด้วยไฟล์ต้นฉบับที่ได้รับ ห้ามแก้หรือประทับ QR หลัง Hash แล้ว
- `SKILLTRUST_PDF_V1` เป็นตัวระบุสูตรเพื่อแยกจาก Hash แบบอื่น ใช้ `abi.encode` **ไม่ใช่** packed encoding หรือ SHA-256 สูตรนี้ต่างจาก helper `computeHash` แต่ใช้ contract เดิมได้ เพราะ `certHash` รับ bytes32 และ `verifyCertificate` เปรียบเทียบค่าเท่านั้น
- Contract ไม่เก็บชนิดสูตรและ salt ผู้ให้บริการต้องแจ้งว่าใบนี้ใช้ **PDF V1** หรือสูตรเดิม การเปลี่ยนสูตรไม่เปลี่ยน Hash ของใบที่ออกไปแล้วและไม่ต้อง redeploy contract
- Issuer ต้องตรวจว่า PDF ตรงกับรหัส หลักสูตร และ Wallet ผู้รับก่อนออก Contract ไม่อ่านข้อความจาก PDF และไม่ยืนยันว่าข้อมูลในเอกสารเป็นความจริงทางธุรกิจ
- ระบบนี้ **ลงทะเบียนหลักฐานของ PDF ที่สถาบันเตรียมไว้** ไม่ใช่เครื่องมือออกแบบ สร้าง หรือเก็บ PDF และไม่ทำ OCR/PDF signature validation

### โหมดเดิม: ข้อมูล 4 ช่อง — ใช้กับใบเดิมหรือสาธิต

เลือก **ข้อมูล 4 ช่อง** ใน Hash Studio แล้วกรอกข้อมูลตรงกับตอนออกใบรับรอง:

```solidity
keccak256(abi.encode(certId, courseId, holderName, salt))
```

เป็นสูตรเดียวกับ `computeHash` ใน Solidity แต่คำนวณในเบราว์เซอร์ **ไม่เรียก helper ผ่าน RPC ด้วยชื่อ/salt** โหมดนี้ตรวจเฉพาะข้อมูล 4 ค่า ไม่พิสูจน์ว่าไฟล์ PDF ไม่ถูกแก้ไข จึงไม่ควรใช้แทน PDF V1 สำหรับใบใหม่ตามสถานการณ์ธุรกิจนี้

**ทั้งสองโหมด:** ใช้ข้อมูลต้นฉบับทุกตัวอักษร ไม่มีการ trim/normalize ภายในสูตร Hash ไม่สุ่ม salt ให้อัตโนมัติในโหมดตรวจสอบ และล้างไฟล์ที่เลือก/ชื่อ/salt เมื่อปิด Hash Studio ไม่มีการเก็บใน localStorage หรือ URL การคัดลอก Hash บนเชนมาเทียบกับตัวเองไม่พิสูจน์เอกสาร ต้องคำนวณจาก PDF/ข้อมูลที่ต้องการตรวจจริง หากใช้ Hash จากระบบอื่น ต้องใช้สูตรและข้อมูลชุดเดิม

### ความหมายของผลตรวจ

| ผล | ความหมาย |
| --- | --- |
| ไม่พบ | ไม่มี certId นี้ใน contract ที่ตั้งค่า |
| มีผลตามสถานะ | มีรหัสและยังไม่ถูกเพิกถอน แต่หากไม่ได้กรอก Hash **ยังไม่ยืนยันความตรงกันของข้อมูล** |
| ตรวจสอบผ่าน | พบใบรับรอง + Hash ตรง + ไม่ถูกเพิกถอน (`valid = true`) |
| Hash ไม่ตรง | ข้อมูลหรือ salt ไม่ตรงกับตอนออก แม้สถานะใบรับรองยังมีผล |
| เพิกถอน | ใช้งานไม่ได้ แม้ Hash จะตรง ประวัติ วันที่ และเหตุผลยังดูได้ |

## ลำดับทดสอบตัวอย่าง

เตรียมบัญชี **A = Admin**, **B = Issuer**, **C = ผู้รับ** และใช้ contract เดียวกันตลอด:

1. A เชื่อม Wallet → **หลักสูตรอบรม** → เพิ่ม `AI-101`, ชื่อ `AI Fundamentals`, รายละเอียด และ `12` ชั่วโมง
2. A → **จัดการสิทธิ์** → เพิ่ม B เป็น Issuer แล้วตรวจสิทธิ์ของ B
3. สลับเป็น B → **ออกใบรับรอง** → ใส่ `ST-2026-001`, เลือก `AI-101`, ระบุ Wallet C
4. เตรียม PDF ที่มีชื่อผู้รับและรายละเอียด → เปิด Hash Studio เลือก **PDF V1** → เลือก PDF ฉบับสมบูรณ์ → เก็บไฟล์ รหัส วิธี Hash และ salt นอกเชน → กดใช้ Hash → ออกใบรับรอง ยืนยันใน Wallet แล้วรอ transaction สำเร็จ
5. สลับเป็น C → **ใบรับรองของฉัน** → ดูรายละเอียดและ QR Code ตรวจว่าผู้รับ/ผู้ออก/เวลา/Hash ตรงกับรายการ
6. เปิดลิงก์ QR ในเบราว์เซอร์ที่ไม่เชื่อม Wallet → ตรวจสถานะด้วยรหัสอย่างเดียว จะระบุชัดเจนว่ายังไม่เทียบ Hash
7. คำนวณ Hash ด้วย **PDF ต้นฉบับ รหัส และ salt เดิม** → ตรวจสอบ ต้องผ่าน ลองแก้ชื่อหรือรายละเอียดใน PDF แล้วบันทึกเป็นอีกไฟล์ ใช้รหัสและ salt เดิมตรวจ ต้องขึ้น Hash ไม่ตรง และลองเปลี่ยน salt ต้องไม่ผ่านเช่นกัน
8. B → **เพิกถอนใบรับรอง** ใส่รหัสและเหตุผลที่ไม่มีข้อมูลส่วนบุคคล → ยืนยัน จากนั้น C ยังเห็นรายการเดิมแต่สถานะเป็นเพิกถอน และ Hash เดิมตรวจไม่ผ่านอีกต่อไป
9. ทดสอบสิทธิ์: C เพิ่มหลักสูตร/ออก/เพิกถอน/จัดการสิทธิ์ไม่ได้ ส่วน B ออกและเพิกถอนได้ แต่เพิ่มหลักสูตรหรือ Issuer ไม่ได้
10. A ลองปิดหลักสูตรแล้วออกใบรับรองใหม่ ต้องเลือกหลักสูตรนั้นไม่ได้; การใช้ certId หรือ Hash ซ้ำจะถูก contract ปฏิเสธแม้รายการเดิมเพิกถอนแล้ว
11. หากทดสอบโอน Admin ให้ใช้ Wallet ทดสอบที่ควบคุมได้ ตรวจว่าผู้ดูแลเก่าเสียสิทธิ์ Admin แต่ยังเป็น Issuer และผู้ดูแลใหม่ได้ทั้งสองสิทธิ์

### สรุปการตรวจโจทย์และกฎธุรกิจ

- **ข้อ 1–6:** มีการจัดการหลักสูตร ออกใบรับรอง เก็บหลักฐาน PDF ตรวจด้วยรหัส/QR เพิกถอนแบบเก็บประวัติ และ Dashboard ตาม Wallet ตามตารางข้างต้น
- **รหัสไม่ซ้ำ:** contract บังคับ `Cert id already used` แม้ใบเก่าถูกเพิกถอน และป้องกัน Hash ซ้ำด้วย
- **ห้ามผู้ไม่มีสิทธิ์ออก/เพิกถอน:** contract ใช้ `onlyIssuer` ทั้งสองฟังก์ชัน ไม่ได้พึ่งการปิดปุ่มใน frontend เพียงอย่างเดียว; Admin ที่ deploy เริ่มต้นเป็น Issuer ด้วย
- **ข้อมูลผู้รับและวันออก:** ชื่อและรายละเอียดอยู่ใน PDF นอกเชน บนเชนมี Wallet ผู้รับและ Hash วันที่ออกใช้ `block.timestamp` ของ transaction ไม่ใช่วันที่ผู้ใช้กรอก
- **ไม่เก็บข้อมูลส่วนบุคคลโดยตรง:** ไม่อัปโหลด PDF ชื่อ หรือ salt ไปยัง Blockchain/RPC แต่รหัสหลักสูตร รหัสใบรับรอง Wallet และเหตุผลเพิกถอนเป็นสาธารณะ จึงต้องใช้รหัสอ้างอิงที่ไม่มีชื่อ/อีเมล/เลขประจำตัวฝังอยู่
- **ขอบเขตผลตรวจ:** เปิด QR หรือค้นรหัสอย่างเดียวตรวจได้เพียงสถานะ ต้องเทียบ Hash จาก PDF จริงจึงตรวจการเปลี่ยนเอกสารได้ และผู้ตรวจต้องยืนยัน contract address กับสถาบันด้วย

## ข้อควรทราบจาก smart contract

- รหัสหลักสูตรและรหัสใบรับรอง **แยกตัวพิมพ์เล็ก/ใหญ่** Frontend trim ช่องว่างหัวท้ายของรหัสในฟอร์มหลักก่อนส่ง แต่สูตร Hash ใช้อักขระตรงตามที่กรอก
- หลังสร้างหลักสูตร ไม่มีฟังก์ชันแก้ชื่อ รายละเอียด ชั่วโมง หรือลบหลักสูตร มีเพียงเปิด/ปิด; Contract อนุญาตชั่วโมงเป็น `0`
- ใบรับรองแก้ไขไม่ได้ รหัสและ Hash ใช้ซ้ำไม่ได้ตลอดอายุ contract รวมถึงหลังเพิกถอน และ `totalCertificates` รวมใบที่เพิกถอนแล้ว
- **Issuer ทุกคน** เพิกถอนใบรับรองใดก็ได้ ไม่ได้จำกัดเฉพาะผู้ออกเดิม ไม่มีฟังก์ชันยกเลิกการเพิกถอน
- `transferAdmin` ไม่ถอนสิทธิ์ Issuer ของ Admin เก่า ผู้ดูแลใหม่ต้องถอนให้เองหากต้องการ และห้ามถอน Issuer ของ Admin ปัจจุบัน
- Dashboard ไม่ใช่ข้อมูลลับ ทุกคนเรียกดูรายการตาม Wallet ได้ การไม่บันทึกชื่อบนเชนไม่ได้ทำให้ Wallet ไม่สามารถเชื่อมโยงกับบุคคลได้
- ชื่อหลักสูตร รายละเอียดหลักสูตร และเหตุผลเพิกถอนเป็นข้อความสาธารณะ ห้ามใส่ชื่อผู้รับหรือข้อมูลอ่อนไหวในช่องเหล่านี้ Salt ช่วยป้องกันการเดาข้อมูลจาก Hash แต่ต้องจัดเก็บ/ส่งให้ผู้ตรวจอย่างปลอดภัย
- Contract ไม่มีรายการ Issuer ทั้งหมดหรือ getter ใบรับรองทั้งหมด หน้าเว็บจึงตรวจสิทธิ์ทีละ address และดูใบรับรองผ่านผู้ถือหรือ certId ไม่สร้างรายชื่อสมมติ
- QR บรรจุ URL เช่น `https://your-site/?certId=ST-2026-001#verify` ไม่บรรจุข้อมูลส่วนบุคคล ลิงก์ `localhost` ใช้ได้เฉพาะเครื่องนั้น หากสแกนข้ามอุปกรณ์ต้องโฮสต์เว็บบน address ที่เข้าถึงได้และตั้งค่า contract เดียวกัน
- ผลตรวจยืนยันข้อมูลตาม contract นี้เท่านั้น ไม่ได้ยืนยันตัวตนผู้รับหรือความน่าเชื่อถือของสถาบันโดยอิสระ ผู้ตรวจควรเช็ก contract address กับสถาบัน
- Public RPC อาจ rate-limit และการอ่านข้อมูลไม่ใช่ snapshot ทั้งระบบในบล็อกเดียว ปริมาณข้อมูลมากควรเพิ่ม pagination/indexer; Tailwind Play CDN เหมาะกับ lab ไม่ใช่ production build

## แก้ปัญหาเบื้องต้น

- **ขึ้นข้อความให้ตั้งค่า address:** ใส่ address ของ DigitalCertificate ที่ deploy บน Sepolia ใน `config.js` แล้วรีเฟรช
- **อ่านข้อมูลไม่ได้:** ตรวจ RPC/อินเทอร์เน็ต/chain/address หาก RPC จำกัดการใช้งาน เปลี่ยนเป็น Sepolia endpoint ที่มีสิทธิ์ใช้
- **ปุ่มทำรายการปิดอยู่:** ตรวจบทบาท Wallet และเครือข่าย Sepolia บัญชีผู้รับทั่วไปทำรายการของ Issuer/Admin ไม่ได้
- **ทำรายการถูก revert:** อ่านข้อความจาก contract เช่น `Cert id already used`, `Hash already registered`, `Course not active` หรือ `Only authorized issuer`; ตรวจ Sepolia ETH สำหรับ gas ด้วย
- **Hash ไม่ตรง:** ตรวจว่าใช้โหมด **PDF V1 / ข้อมูล 4 ช่อง** ตรงกับตอนออก ใช้รหัสและ salt เดิม สำหรับ PDF ต้องเป็นไฟล์ต้นฉบับทุกไบต์ แม้การ Save ใหม่หรือแก้ metadata ก็ทำให้ไม่ตรงได้ อย่าสุ่ม salt ใหม่ตอนตรวจ
- **ฟอนต์ไม่ขึ้น:** ตรวจไฟล์ `LINESeedSansTH_W_Rg.woff2` อยู่ข้าง `index.html` และใช้ HTTP server
- **QR ไม่ขึ้น:** ตรวจว่าโหลด QRCode.js CDN ได้ ยังใช้ปุ่มคัดลอกลิงก์ได้
- **คัดลอกไม่ได้:** ใช้ `localhost` หรือ HTTPS ที่อนุญาต Clipboard API หรือคัดลอกข้อความด้วยตัวเอง
